# Run worker 0.0.3b 发布说明

> 发布日：2026-11-12
> 功能补丁：彻底删除对话、Composer 增强菜单、精准 Token 计量、应用内一键升级、自我改进与更像人，
> 并附带一轮全面的 Bug 排查修复与算法优化。
> 无破坏性变更，`settings.json` 结构仍为 version 1（新增 `persona.humanize`，旧配置自动补默认值），

> 应用内可点击标题栏版本号，或进入「设置 → 更新 → 查看本次更新内容」查看同样的内容。

## 一、删除对话，这次是真的删干净

之前「删除对话」只删会话文件与索引条目。0.0.3b 把它做成一个完整的擦除流程：

| 清理对象 | 说明 |
| --- | --- |
| 会话文件与索引 | `<id>.json`、同名前缀的辅助文件（`<id>.trace.json`、`<id>.lock` 等）、`index.json` 中的条目 |
| 消息与工具记录 | 随会话文件一并删除 |
| 派生长期记忆 | 该会话自动抽取的记忆（`auto:<id>`）、工具写入的记忆（`tool:<id>`）、用户提交的纠正（`feedback:<id>`） |
| 产物文件 | 该会话生成的图片 / 脚本 / 生成物（`.runworker-artifacts/<id>/`），以及 0.0.3a 及更早版本散落在产物根目录的旧文件 |
| 在途任务 | 删除前中止该会话全部运行中的 run，并加「删除屏障」拦截后续落库、工具写入与记忆抽取，杜绝删完又被写回复活 |

删除完成后，界面会列出**实际擦除的数量**；若有文件被占用删不掉，会明确提示关闭相关程序后重试，不再假报「已彻底删除」。先删文件、成功后才改索引，避免出现「索引空了但文件还在」的孤儿。

侧栏新增「清空全部」入口，一次性清掉全部会话、索引、派生记忆与整个产物根目录。

## 二、精准显示 Token

过去界面多处用字符数粗估，服务端不返回 usage 时甚至显示 0 token。现在：

- **逐轮累加**：多步工具调用会向模型发多次请求，本轮统计把每一次请求的 `prompt_tokens` / `completion_tokens` / `total_tokens` 全部累加，而不是只取最后一轮。
- **完整数字**：输入框底部、消息元信息、右侧轨迹栏都显示完整数字（带千分位），不再用 `1.2k` / `3.4M` 缩写掩盖真实值。
- **来源如实标注**：服务商返回 usage 时标「精确」；未返回时用本地估算并标「约」；混合时标「部分估算」并说明几轮是精确值。费用仍按公开单价估算，文案保持「估算费用」。
- **不误导**：演示模式、流式生成中都以「约 / 实时估算」标注；「设置 → 思考过程 → 显示思考 token」开关现在真正生效。

## 三、Composer 增强菜单

输入框左侧新增「＋」菜单，六类能力一屏可达：

- **添加文件**：从电脑选择文件加入本次对话
- **引用对话文件**：列出本对话的历史附件与生成产物，可重新带上（缺失文件会标记且不可选）
- **模式**：直给 / 均衡 / 教学 / 极简，并可开关「更像人」
- **专家**：8 个 Agent，与原有下拉同步
- **技能**：总结要点、改写润色、解释原理、拆解任务、审查找错、中英互译，点击后把模板插入输入框
- **连接器**：显示已连接的 MCP 服务状态，一键进入 MCP 管理面板

## 四、自我升级、自我改进、更像人

**自我升级**：发现新版本后，侧栏出现提示；进入「设置 → 更新」点「下载并安装」，应用会流式下载安装包（实时进度）、用发布信息里的 SHA-256 自动校验、通过后拉起 `/S` 静默安装器并退出自身完成覆盖。校验不通过会立即删除下载文件并中止；仍可随时改用「打开下载页」手动升级。整个过程由你点击确认后才会开始。

**自我改进**：任意助手回复下方新增「纠正这条回复」。写下的规则会以 `instruction` 类型进入长期记忆，系统提示词把这类【要求】标为最高优先级；同时带上会话来源，彻底删除该对话时会一并清除。

**更像人**：新增 `persona.humanize` 人设层（默认开启）——自然平实的语气、记住本轮与长期记忆里已达成的约定、不确定时先简短确认、被纠正时先承认再直接改，而不是辩解或复述旧答案。

## 五、全面排查修复的 Bug

主进程：

- 流式输出中断后整轮重试导致文本重复（增量计数此前恒为 0）
- 多步工具调用把各轮过渡文本拼进最终落库的助手消息
- `shell.exec` / `python.exec` 超时后 Promise 永久挂起；Windows 下无法结束孙进程（现用 `taskkill /t /f` 杀进程树 + 2 秒兜底）
- 含空格的 Python 路径被加引号导致 `spawn` ENOENT；临时 `.py` 脚本无限累积
- `net.fetch` 把 404/500 错误页写成「下载成功」、下载无体积上限、未走文件写入权限检查
- `fs.read` 按行参数边界错误与倒挂区间；`fs.delete` 忽略 `recursive` 参数强制递归删目录
- 原子写在 Windows 目标被占用时静默丢数据并残留 `.tmp`；定时任务多个 tick 并发、`task-output` 无限累积
- 长期记忆合并相似条目后丢失来源，导致按会话删除记忆误删/漏删

渲染层：

- 定时任务触发的 run 写入 `messageId: ''` 孤儿，导致输入框永久锁在「停止」
- 删除会话后残留孤儿 run 与授权请求；切换会话 / 点停止时状态不回滚
- `stop()` 找不到本会话 run 时把 `undefined` 传给 abort，误杀全部运行中的任务
- bootstrap 失败时永久卡在启动画面且错误提示不渲染
- 并发发送造成多条占位消息与跨会话内容串台
- `run:end` 替换消息 id 导致用户展开的参数 / 思考面板被重置
- 设置页更新信息用本地副本，后台自动检查的结果不刷新；系统主题双源不一致
- 思考面板折叠状态下仍每 200ms 重渲染

## 六、算法与易用性优化

- 工具循环按总字符预算滚动裁剪上下文，保留 system 与首条 user、按「工具轮整组」删除以维持 `tool_calls` 与 tool 消息配对，避免多步调用把请求体撑到 413
- 工具调用去重改用键排序的稳定序列化，参数键顺序不再影响判重
- cron 下次执行时间由逐分钟暴力搜索（上限约 52 万次循环）改为按「月 → 日 → 时 → 分」字段直接跳进
- 定时任务 tick 加互斥锁、任务产物按数量滚动清理；长期记忆归一化结果缓存
- 流式 Markdown 解析改为节流；Composer 空首页不再显示全 0 的 token 条
